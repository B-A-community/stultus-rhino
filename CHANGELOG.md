# Журнал изменений

Нумерация версий: третья цифра растёт с каждой итерацией, вторая — при
существенных изменениях, первая станет 1 в момент релиза. Версия хоста —
в `host/StultusRhino.csproj` (`<Version>`, оттуда её берёт сборщик пакета и
`manifest.yml`), версия gateway и окна — `server/src/version.ts` и
`server/package.json`. Gateway сообщает окну минимальную версию хоста
(`HOST_MIN_VERSION`): старее — окно предлагает обновить плагин.

## 0.1.1 — 2026-09-18

### Добавлено

- Инструмент `grasshopper` (`server/rhino/grasshopper.py`): канвас (open/new/
  clear/status/list/zoom), поиск компонентов в библиотеке (find) и добавление
  по guid/имени (add), слайдеры (slider/set), Python 3 компоненты с входами,
  выходами и кодом (script — создание и обновление по id; выходы
  маршалятся в ветки данных), провода (wire/unwire), решение с отчётом об
  ошибках компонентов (solve, `problems`), чтение выходов с габаритами (read),
  сохранение/загрузка `.gh` (save/load). Снимок сцены показывает канвас.
- Пример `examples/kafd/`: станция метро KAFD (Заха Хадид) — слайдеры
  этажности, высоты этажа, габаритов и решётки → Python-компонент строит
  оболочку-лофт, диагрид, плиты этажей по сечениям оболочки, ядра и колонны;
  переключатель «запечь» кладёт геометрию на слои `KAFD::*`.
- Живой прогон `tests/live_tests.py`: хост, скрипты инструментов, приёмы
  моделирования, Grasshopper, ходы модели через окно (Claude и Codex).

### Исправлено

- Хост после решения Grasshopper терял ответ скрипта: GH подменяет
  `sys.stdout`; теперь поток возвращается перед печатью результата.
- Проверка сервера и скачивание пакета — из окна (WebView2), не из
  Rhino.exe: у Rhino может быть закрыт выход в сеть брандмауэром; gateway
  отдаёт `/health` и `/download` с CORS. Хост требует gateway ≥ 0.1.1,
  gateway требует хост ≥ 0.1.1 (`HOST_MIN_VERSION`).
- Мост разработки без окна держит один запасной Bridge (запись Undo хода
  закрывалась не тем экземпляром).
- Grasshopper: первый запуск в сессии показывает модальные «Getting started»
  и «Loading Errors» — скрипт закрывает их таймером; удаление параметров
  компонента без бесконечного цикла; Decimal слайдеров → float; новые
  параметры Python-компонента регистрируются (`RegisterInputParam`), выходы
  маршалятся (`MarshOutputs`), действие `preview` (превью канваса off/wire/shaded).
- Gateway: `done` уходит в окно только по концу потока провайдера. Codex
  присылал `turn.completed`, а следом ещё вызов `ask_user`; окно снимало
  «занято», следующее сообщение стартовало параллельно, и продолжение
  сессии падало («Reading prompt from stdin», новая сессия).

## 0.1.0 — 2026-09-17

Первая версия. Основа — Stultus 0.2.10 для SketchUp: тот же gateway
(Node, Claude Agent SDK + codex-sdk, MCP по localhost), тот же дизайн окна
Graphite, та же копилка приёмов и постпродакшн через Codex.

### Хост (плагин Rhino 8, C#, .NET 8)

- Тонкий хост: окно (Eto Form + WebView2) грузит страницу с gateway
  (`/ui/`), мост `chrome.webview.postMessage` ↔ `Stultus.receive`; всё,
  что меняется часто, приезжает с сервера.
- Исполнение Python 3 через RhinoCode (`Rhino.Runtime.Code`): аргументы
  как `__stultus_args__`, ответ — переменная `result`, stdout и трассировки
  (без пути к временному файлу, с верными номерами строк).
- Одна запись Undo на ход модели: открывается первым `execute_python`,
  закрывается по концу хода; упавший вызов удаляет созданные им объекты.
- Переписка, сессии провайдеров, архив и цвет окна — в пользовательском
  тексте документа (секция `BACommunity_StultusRhino`, лимит 150 КБ).
- Настройки рабочего места (адрес, пропуск, провайдер, модель, тема,
  положение окна) — в настройках плагина Rhino.
- Самообновление: gateway говорит минимальную версию хоста и даёт `.yak`,
  хост скачивает и ставит его через yak.
- Команды `Stultus` (окно) и `StultusSettings` (страница подключения).
- Мост разработки `127.0.0.1:8799` (`STULTUS_RHINO_DEV=1`): Python, вызовы
  моста, JS в окне — для прогонов без ручных кликов (`tests/dev.py`).

### Gateway

- Раздача окна и Python-скриптов инструментов (`/ui/`, `/ui/tools.js`
  из `server/rhino/*.py` с общим `_common.py`), пакетов хоста (`/download/`).
- Инструменты MCP: `execute_python`, `get_scene`, `select`,
  `take_screenshot` (вид, показать всё, режим отображения), `named_views`,
  `render_viewport` (обычный и большой кадр 4K/6K/8K), `save_recipe`,
  `get_recipe`, `undo`, `ask_user`.
- Подсказка модели для Rhino: единицы документа, GUID, слои, блоки,
  замкнутые полисурфейсы, проверка результата.
- Docker: проект Compose `stultus-rhino`, порт 8792, сеть хоста, тома для
  входа Claude/Codex и данных; сборка через прокси виртуалки.

### Проверено вживую (Rhino 8.30, Windows, Codex GPT-6 Astra)

- «Построй куб 500 мм…» → execute_python → select → get_scene, куб «Тест»
  на слое «Тест» 500×500×500, ход 26 с; Ctrl+Z (`_Undo`) убирает всё одним
  шагом; переписка и сессии в документе.
- Просьба снимка → карточка → снимок Shaded с показом всей модели → модель
  описала кадр; продолжение сессии между ходами.
- Скрипты инструментов по отдельности: снимок сцены с выделением по-русски
  («1 экземпляр блока «Кружок» из 2, 1 полисурфейс: Стол»), select с zoom,
  снимок стандартного вида с возвратом камеры и имени вьюпорта, именованные
  виды (add/list/activate), вложения, кадры постпродакшна (store/read/export).

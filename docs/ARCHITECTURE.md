# Архитектура Stultus Rhino

## Зачем именно так

Четыре решения, из которых следует всё остальное. Первые три унаследованы
от [Stultus](https://github.com/B-A-community/stultus) для SketchUp,
четвёртое — новое.

**1. Нейросеть — на общей виртуалке, не на рабочих машинах.** Подписки и
ключи одни на бюро, лежат в `.env` на сервере. Плагин знает только адрес и
пропуск. Заменить модель, поднять лимит, сменить провайдера — правка на
сервере.

**2. Соединение исходящее, из окна плагина.** Плагин не слушает портов:
нет конфликтов портов между окнами, нет правил брандмауэра, окно работает
из любой сети, откуда виден gateway. Сеть живёт в JS окна, а не в хосте:
Rhino-поток занят исполнением Python, и ждать в нём ответа модели нельзя.

**3. Плагин — это MCP-сервер для модели.** Gateway выставляет одни и те же
десять инструментов как MCP-сервер `stultus` и подключает его к процессу
Claude Code или Codex. Добавить провайдера — один файл в `server/src/providers/`.

**4. Хост в Rhino — тонкий; окно, скрипты инструментов и подсказка приезжают
с сервера.** Обновление плагина без переустановки: сотрудник не делает
ничего, обновляется только gateway. Хост (C#) умеет ровно то, что нельзя
прислать: показать страницу, исполнить Python в Rhino, держать запись Undo,
хранить переписку в документе и настройки на машине, обновить сам себя.

## Ход, по шагам

1. Пользователь жмёт «Отправить». JS просит хост исполнить скрипт
   `scene_state` (из tools.js), кладёт снимок сцены к тексту и шлёт `chat`
   в gateway.
2. `chat.ts` берёт провайдера, подставляет `resume`/`thread_id` из файла
   модели (окно прислало их в `hello`), запускает генератор.
3. Провайдер стартует процесс модели с MCP-сервером этого окна. Модель зовёт
   `execute_python` → MCP-обработчик шлёт `tool_call` в окно → JS зовёт хост
   `execute_python` → хост открывает запись Undo хода (если ещё нет), исполняет
   код через RhinoCode, возвращает `result`/stdout → `tool_result` → MCP
   отвечает модели.
4. `get_scene`, `select`, `take_screenshot`, `named_views` — то же, но JS
   передаёт хосту Python-скрипт инструмента из tools.js и аргументы; хост
   исполняет без записи Undo (или в записи хода для `named_views`).
5. Текст ответа стримится в окно, карточки инструментов JS рисует сам.
6. `done` с расходом. JS сохраняет переписку (`save_history`) и сессию
   (`save_sessions`) в документ через хост и закрывает запись Undo (`turn_end`).

Снимок вьюпорта — тот же путь, только между `tool_call` и Python стоит
пользователь: карточка с кнопками. Отказ — обычный `tool_result` с
`ok: false`, модель продолжает.

## Undo

`RhinoDoc.BeginUndoRecord` не вкладывается: пока запись открыта, вторую не
открыть. Поэтому одна запись на ход (как в RhinoAI у McNeel), а не на вызов:
Ctrl+Z после хода откатывает всё, что сделала модель. Цена: упавший вызов
нельзя откатить отдельно — хост удаляет объекты, созданные этим вызовом
(сравнение множества id до и после), а об изменениях существующих объектов
говорит модели в ответе. Инструмент `undo` закрывает запись, выполняет
`_-Undo` и следующий вызов откроет новую запись.

## Обновления

- **Окно и скрипты**: `/ui/*` отдаются без кэша; окно грузится при каждом
  открытии. `tools.js` собирается на каждый запрос из `server/rhino/*.py`
  (общий `_common.py` приклеивается в начало).
- **Подсказка модели**: `server/src/prompt.ts`, на каждый ход.
- **Хост**: `welcome` несёт `host_min` и `host_outdated`; окно показывает
  сообщение с кнопкой «Обновить плагин» → хост скачивает
  `/download/<пакет>.yak` и запускает `yak install`; после перезапуска Rhino
  работает новая версия. Пакеты кладутся в `PACKAGES_DIR` на gateway
  (`/opt/stultus-rhino/data/packages`).

## Границы и страховки

- **Произвольный Python исполняется на рабочей машине.** Это осознанно.
  Защита — Undo на ход, пропуск на gateway, MCP-эндпоинт только на localhost
  с уникальным bearer на соединение.
- **Таймаут инструмента** (10 мин) на стороне gateway: если окно закрылось
  посреди хода, модель получает отказ, а не висит.
- **Один ход на окно.** Второе сообщение во время хода отклоняется.
- **Потолок кругов** (`MAX_TURNS`), **предел вызовов за ход**
  (`TURN_MAX_TOOL_CALLS`) и **мягкий бюджет токенов** (`TURN_TOKEN_BUDGET`).
- **Лимит переписки в документе** — 150 КБ.
- **Мост разработки** (`127.0.0.1:8799`) выключен по умолчанию: он
  исполняет любой код от любого локального процесса.

## Что намеренно не сделано в 0.1

- Grasshopper: снимок канваса и инструменты для компонентов (см. ROADMAP).
- Рендер штатным рендерером Rhino (`_Render`) как инструмент.
- Лимит времени на Python: прервать CPython посреди RhinoCommon безопасно
  нельзя.
- Rhino для Mac: хост собран на Eto, WebView2 и мост `chrome.webview` —
  Windows; на Mac канал Eto другой (`webkit.messageHandlers`).
